الاختبار الإضافي الكامل ونتيجته النهائية موثقان في `QA/verified-e2e.log` ضمن حزمة الاختبارات. يشمل:

1. تقديم طلب حقيقي إلى Express وحفظه في SQL، رفض الهاتف غير المطابق للدولة، ومنع تكرار الطلب.
2. رفض موافقة الطالب على الطلبات، ورفض الدعوة قبل القبول، ثم قبول الإدارة وإنشاء الدعوة. رسالة الدعوة التُقطت عبر مزود بريد محاكى داخل الاختبار فقط.
3. افتعال فشل قاعدة بعد استهلاك الرابط؛ التحقق من التراجع، ثم نجاح المحاولة التالية ورفض تكرار استخدامها.
4. تسجيل دخول الطالب، رفض كلمة المرور الخاطئة، ومنع وصوله لتشخيص الإدارة.
5. رسائل فعلية بين متصفحين مستقلين عبر Express وSQL؛ ظهور رسالة المدير لدى الطالب، ثم ظهور رد الطالب لدى المدير بالتحديث التلقائي.
6. اختبار عدم اعتبار رسالة وصلت لاحقًا مقروءة قبل تحميلها، وحفظ مسودة عند تبديل الخدمة.
7. فشل إعادة كلمة المرور والتراجع الآمن، ثم نجاحها وإبطال الجلسات وروابط الاستعادة الأخرى، ورفض الرابط المنتهي.
8. تقديم النموذج من المتصفح حتى حفظ صف واحد في قاعدة البيانات، وفحص قائمة تسع دورات ورابط تفاصيلها إلى التقديم.
9. رفض parent وteacher بقيود القاعدة، ومنع تكرار رسالة التواصل.

سجل الاختبار يتضمن أخطاء متعمدة لاختبار التراجع وتعطل المخطط؛ نتيجة النجاح النهائية هي المرجع، وليست تلك الأخطاء رسائل من الإنتاج. أُصلحت أيضًا أخطاء في تجهيز بيانات واختيارات الاختبار أثناء تشغيله؛ لم تُغيّر الواجهة للتحايل عليها.

## ما لم يمكن التحقق منه

- لا وصول إلى مشروع Replit الجاري أو عمليته أو قاعدة بياناته؛ لا أزعم أن خطأ خدمة الإرسال على الاستضافة انتهى قبل رفع المصدر المطابق وإعادة تشغيله.
- لا اختبار إرسال إلى بريد طالب حقيقي أو إشعار هاتف فعلي، ولا اتصال فعلي بـ Gemini أو Zoom أو Google أو Cloudflare Turnstile. حالات المحاكاة وغياب الإعداد لا تكفي لإثبات صلاحية مفاتيحك.
- ترحيلات قاعدة جديدة اختُبرت معزولة، لكن لم يُنفذ ترحيل على قاعدة مستخدمة. حالة مخطط الإنتاج وبياناته غير معروفة.
- لم أجر تثبيتًا نظيفًا جديدًا عبر `npm ci`؛ استخدمت الاعتماديات المتاحة بعد مطابقة ملف القفل، ولم تتغير الاعتماديات.
- اختبارات الواجهة الموسعة تستخدم استجابات اختبار. الاختبار بين متصفحين ونموذج التقديم يستخدم الخادم وقاعدة الاختبار فعليًا. لا أدّعي اختبار كل زر على بيانات إنتاج.
- لا تدقيق اختراق شامل أو مراجعة تبعيات أمنية جديدة أو قياس Lighthouse في هذه الدفعة.
- بقي تحذير Vite من حزمة JavaScript أولية كبيرة: نحو 519.25 kB، مضغوطة 169.63 kB. لم أُجر تحسينًا شاملًا للحزم هنا.

## طريقة تركيب التحديث

1. احفظ نسخة من مشروعك وقاعدة بياناتك والأسرار في مكانها الحالي.
2. عند استخدام حزمة التعديلات: انسخ محتويات `files/` إلى جذر المشروع مع الحفاظ على المسارات واستبدال الملفات الموافقة. لا توجد ملفات مطلوبة للحذف. يجب رفع ملفات الخادم والواجهة معًا، بما فيها `server/account-tokens.ts`.
3. أو استخدم حزمة المصدر الكاملة في مجلد جديد، ثم أعد ربط أسرار الاستضافة الحالية. لا تنسخ أسرارًا إلى Git أو إلى ملفات التسليم.
4. على الاستضافة النهائية نفّذ `npm ci` ثم `npm run verify`. اضبط `TZ=UTC` كما في دليل النشر الموجود.
5. أعد تشغيل الخادم بعد البناء باستخدام أمر الاستضافة الموافق؛ تشغيل الإنتاج في المشروع هو `npm start`. رفع ملفات الواجهة وحدها لا يحدّث مسارات API في عملية Node القديمة.
6. لا يتطلب هذا التحديث ترحيلًا جديدًا. إذا أظهر التشخيص أن قاعدة قديمة تفتقد أعمدة، راجع ملفات الترحيل الموجودة والدليل الموافق بعد أخذ نسخة احتياطية؛ لا تستخدم ترحيل قاعدة جديدة فوق قاعدة قائمة.
7. سجّل دخول المدير وافتح تشخيص الاتصال ثم فحص حفظ الرسائل الآمن. اختبر بحساب طالب مخصص لك: طلب تقييم، قبول، دعوة، تفعيل، دخول، ثم رسالة في الاتجاهين.
8. اختبر Zoom والبريد وGoogle عبر إعداداتك الفعلية، وتحقق من الاستجابة ومن جهة الاستقبال. لا تشارك قيم المفاتيح في الدردشة.
