# زر المحادثات الأخضر وخطأ مسار التشخيص

## ما تغيّر
- زر المحادثات الدائري أصبح أخضر الأكاديمية بتدرج `#237158` إلى `#165447` ونص وأيقونة بيضاء.
- عند فتح المحادثات أو الإشعارات على الكمبيوتر والتابلت الأكبر من 600 بكسل، الخلفية واضحة بلا تمويه ولا تعتيم. تبقى النافذة قابلة للإغلاق بـ Escape أو النقر خارجها.
- النوافذ ما زالت تملأ الهاتف عند عرض 600 بكسل أو أقل. بقية أسطح الوضع الليلي والنهاري تحتفظ بالتصميم الحالي.

## معنى الرسالة التي ظهرت لديك
«مسار الخدمة غير موجود في الخادم الحالي» تظهر عندما يعيد طلب الخدمة HTTP 404. داخل «تشخيص الاتصال» الطلب المقصود هو:

`GET /api/admin/service-diagnostics`

المسار موجود في النسخة المسلّمة: يعرّفه `server/service-diagnostics.ts`، ويسجله `server/portal.ts`، وتستدعيه `server/routes.ts`. إنشاء ملف فقط دون تسجيله، أو تشغيل نسخة Express قديمة، أو توجيه الطلب إلى خادم آخر، يمكن أن يؤدي إلى 404.

الرسالة لا تثبت سبب خطأ إرسال الرسائل الأصلي؛ تعني أن فحص السبب نفسه لم يصل إلى المسار المطلوب. الخطوة التالية هي تشغيل الواجهة والخادم من النسخة المتطابقة.

## الخطوات العملية
1. خذ نسخة احتياطية من ملفات المشروع. احتفظ بـ Secrets وقاعدة البيانات الحالية.
2. استخدم النسخة الكاملة لهذه الحزمة لتحديث المشروع كله إذا كنت لا تعرف أي ملفات خادم رُفعت سابقًا. لا تنشئ قاعدة بيانات جديدة ولا تحذف بيانات الطلاب.
3. حزمة التعديلات تحتوي CSS الجديد والتقرير، بالإضافة إلى مجلد الخادم `server` كاملًا واعتماداته المشتركة `shared` وملفات البناء `script` وملفات تعريف الحزم من النسخة الحالية. هذه ملفات مطابقة للنسخة، حتى إن لم يتغير نصها في هذا التعديل.
4. افتح الطرفية من المجلد الذي يحتوي `package.json` وشغّل:

```bash
npm ci
npm run check
npm run lint
npm run build
```

5. أوقف العملية القديمة من وسيلة تشغيل المشروع ثم شغّل العملية المناسبة:
   - للمعاينة أثناء التجهيز: `npm run dev`.
   - لتشغيل الإنتاج بعد بناء النسخة: `npm start`.
   لا تشغّل الاثنين على المنفذ نفسه. تغييرات الخادم لا تصل إلى نسخة الإنتاج إلا بعد البناء وإعادة تشغيل عمليتها.
6. افتح الأكاديمية من عنوان المعاينة الجاري تشغيله وسجّل الدخول كمدير. حدّث الصفحة بـ Ctrl+Shift+R.
7. داخل نافذة المحادثات أعد فتح «تشخيص الاتصال». يجب أن يظهر فحص المخطط وإعدادات Gemini والبريد، لا 404.
8. إذا بقي 404، وأنت مسجّل كمدير، افتح في التبويب نفسه العنوان:

```text
https://YOUR-CURRENT-APP-HOST/api/admin/service-diagnostics
```

استبدل `YOUR-CURRENT-APP-HOST` باسم المضيف نفسه الظاهر في شريط عنوان الأكاديمية، دون إضافة `/ar` أو `/dashboard` قبل `/api`.

- `200` مع بيانات JSON: المسار يعمل؛ تأكد أن نافذة الأكاديمية تستخدم المضيف نفسه وحدّث الصفحة.
- `401`: سجّل الدخول من المضيف نفسه ثم أعد المحاولة.
- `403`: الفحص يحتاج حساب المدير.
- `404`: الخادم أو التوجيه على هذا المضيف لا يقدم المسار؛ راجع العملية الجاري تشغيلها وملفات الخادم.
- `503`: وصل الطلب إلى الخدمة، لكنها تحتاج مراجعة قاعدة البيانات أو المخطط حسب رمز الخطأ.

9. بعد نجاح التشخيص، افتح «فحص حفظ الرسائل بأمان». يحاول الحفظ داخل معاملة ثم يلغيها؛ لا تصل رسالة للطالب. أرسل نتيجة الفحص ورقم المتابعة إذا استمر الخطأ.

لا تُرسل مفاتيح Gemini أو Resend أو SESSION_SECRET أو DATABASE_URL. لا تُعطّل حماية تسجيل الدخول أو المصدر لحل 404.

## حدود التحقق
جرى التحقق من النسخة المحلية فقط. لم نغيّر استضافة المشروع الحية أو نصل إلى سجل خادمها؛ لا يمكن تأكيد سبب 404 على المضيف الحي دون تنفيذ الخطوات أعلاه.

## نتائج التحقق لهذا التعديل
- `npm run check`: نجح.
- `npm run lint`: نجح.
- `npm run build`: نجح. بقي تنبيه حجم حزمة الواجهة الموجود سابقًا: 516.77 kB، أو 168.93 kB مضغوطة.
- 232 تحققًا للواجهة: أخضر الزر في الوضعين، انعدام تمويه/تعتيم الكمبيوتر، ملء الشاشة على الهاتف، الإغلاق واستعادة التركيز، عدم وجود تجاوز أفقي. عروض 390 و1024 و1440، العربية والإنجليزية، المدير والطالب، الليل والنهار. لا أخطاء JavaScript في هذا الاختبار.
- 155 تحققًا للخادم على قاعدة PGlite معزولة و13 ترحيلًا: صلاحيات التشخيص، حجب الأسرار، إرسال الرسائل، منع التكرار، التراجع الآمن وتشخيص المخطط. لم تُتصل حسابات الإنتاج؛ استجابات المزودين محاكاة في الاختبارات فقط.
- اللقطات المرفقة توضح التصميم ببيانات اختبار معزولة، وليست حسابات حقيقية في أكاديميتك.
- لا تغيير في قاعدة بيانات الإنتاج ولا ترحيل تلقائي. لا مفاتيح فعلية في الحزم.
