# تقرير إصلاحات الصور والخدمات

## مشكلات تأكدت في المصدر وأُصلحت

1. دائرة الإنجاز بلا تعريفات CSS الأساسية الخاصة بـ SVG. أضيف fill:none وstroke وعرض ثابت متجاوب ونسبة في المنتصف ووسيلة إيضاح واضحة.
2. زر التواصل يستخدم متغيرًا معرفًا على النافذة، وليس على الزر. ثُبّت اللون الأخضر على الزر نفسه. جرى ضبط ألوان النافذة الداكنة وتباين التبويبات، وتصحيح هامش سالب كان يقص أعلى بطاقة المحادثة الحديثة.
3. الخلفيات تنتهي عند حافة مقدمة مستقلة لها لون وحد؛ أضيف قناع شفافية تدريجي حتى سطح الصفحة، وأُلغي الحد السفلي والخلفية المستقلة. روجعت لقطات داخلية للداشبورد والهاتف وصفحتي الدورات وكيف تبدأ.
4. صفحة الخدمات كانت تجمع طلبات إلى /admin/curriculum و/admin/materials/assignments، بينما سياسة المشروع تعطلهما بحالة 410. استُخدم /api/portal للطلاب والبرامج وأزيلت طلبات/واجهة Drive المعطلة. لم تُحذف سجلات أو خدمات قاعدة بيانات.
5. تشخيص الحفظ القديم يكتفي بوجود الجداول والعمودين read_at وrequest_key. أضيف فحص الحقول الإلزامية القديمة بلا defaults، واحترام أعمدة identity الصحيحة، وفحص أسماء المشغلات. لا يُعرض الفحص البنيوي على أنه اختبار حفظ ناجح.
6. أخطاء PostgreSQL أصبحت تعيد للمدير فقط بيانات تشخيص محدودة: الرمز والمرحلة وأسماء جدول/عمود/قيد صحيحة نحويًا. لا نصوص SQL ولا قيم رسائل ولا أخطاء خام. يبقى الخطأ عامًا للطالب.
7. صفحة الخدمات تعرض callback الفعلي لـ Google وتحذر عند اختلاف أصل المتصفح عن FRONTEND_URL. عولجت بعض أخطاء قاعدة البيانات في مسارات التكامل برسائل محددة بدل internal_error العام.

## الاختبار

- npm run verify: نجح TypeScript وLint وبناء الإنتاج.
- 203 فحوص معزولة: 117 فحص SQL/API/HTML ومنطق، و32 حالة داشبورد، و54 زيارة صفحات عامة.
- واجهة المدير والطالب، اللغتان، RTL/LTR، الوضعان الليلي والنهاري، عرض 320 و390 و768 و1440 للداشبورد.
- تأكيد لون الزر المحسوب وغياب fill الأسود في دائرة الإنجاز وعدم قص أول بطاقة بالهيدر وعدم وجود تمرير أفقي.
- صفحة الخدمات تُحمّل دون الاعتماد على مسارات 410، وحقل callback ظاهر للمدير، ويُرفض وصول الطالب إليه.
- إرسال فعلي عبر المتصفح إلى API وقاعدة PostgreSQL معزولة داخل عملية الاختبار، مع قراءة ورد وصلاحيات وتراجع عند الفشل.
- محاكاة قاعدة قديمة بعمود إلزامي إضافي: اكتشفه التشخيص وأعاد خطأ PostgreSQL 23502 مع اسم العمود للمدير فقط، دون تسريب محتوى الرسالة.
- محاكاة تعارض قيد messages_pkey: أظهر فحص الحفظ الآمن الاسم والرمز دون نص الخطأ الخام.
- OAuth start يبني عنوان العودة المعروض نفسه وحالة عشوائية ولا يضع Client Secret في الرابط. حالة callback غير صحيحة رُفضت دون الاتصال بخدمات إنتاج خارجية.

## ما لم يُثبت

لم يتوفر اتصال بقاعدة Replit الحقيقية أو سجل الخطأ ذي المرجع 2a587daa-4db7-4892-a3ad-1230faa8f20e. لذلك لم يُحدد القيد أو المشغّل الذي يسبب فشل الحفظ هناك ولم تُعدل قاعدة الإنتاج. قد يتطلب حلّه ترحيلًا أو تصحيح sequence أو صلاحية بعد معرفة رمز PostgreSQL الفعلي. لا يُعد تحسين التشخيص إصلاحًا مؤكدًا لهذا الخطأ الخارجي.

لم تُختبر مفاتيح Zoom وGoogle وResend وGemini على الحسابات الفعلية. خطأ Google redirect_uri_mismatch يحتاج مطابقة الإعداد في Google Cloud Console، وهي خطوة خارج ملفات المشروع. لا يغير هذا التحديث أسرار Google أو FRONTEND_URL تلقائيًا.

لا اعتماديات ولا ترحيلات جديدة في هذه الدفعة. تنبيهات أدوات البناء وحجم الحزمة المذكورة في التقرير السابق لا تزال أعمال صيانة منفصلة. لم يُنفذ تراجع شامل إلى تصميم تاريخي؛ صُححت العيوب المحددة مع الحفاظ على الصفحات ومحتواها وهوية الأكاديمية.
