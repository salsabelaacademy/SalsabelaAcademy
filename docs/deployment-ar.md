# نشر سلسبيلا: خادم Node دائم + PostgreSQL + Cloudflare DNS

هذا دليل إعداد قابل للتنفيذ لاحقًا. لم يُنشر الموقع، ولم تتغير DNS أو أسرار حساباتك. المسار المختار هو **الخيار A**: خدمة Node Web Service على Render مع PostgreSQL مدارة. لا ترفع `dist/public` وحده إلى Cloudflare Pages؛ ذلك سيفقد المصادقة وقاعدة البيانات والتكاملات والمهام.

## 1. تجربة التعديلات على مشروعك الحالي

1. خذ نسخة من المشروع وقاعدة البيانات قبل استبدال الملفات.
2. استخدم الحزمة المصححة الحالية. تعليمات استعادة الكورسات واختبار هذه النسخة موجودة في `START-HERE-AR.md` بجذر المشروع؛ لا توجد ملفات صفحات محذوفة في هذا الإصلاح.
3. لا ترفع `.env` أو أسرار Replit إلى Git. لا تضع أي مفتاح في متغير يبدأ بـ `VITE_`.
4. استخدم Node 22.16 أو أحدث ضمن 22 أو 24، ثم `npm ci`.
5. إن كانت قاعدة البيانات عند المرحلة الرابعة، نفّذ `npm run db:migrate:phase5` مرة واحدة. إن كانت عند المرحلة الثالثة، نفّذ `npm run db:migrate:phase4` أولًا. لا تعاود ترحيل baseline على قاعدة موجودة، ولا تستخدم `db:push` لتجاوز SQL الخاص بالمحفزات.
6. نفّذ `npm run check` ثم `npm run lint` ثم `npm run build`.
7. أعد تشغيل المعاينة بـ `npm run dev`. أمر `npm run dev` يقرأ `.env` المحلي إذا كان موجودًا؛ أسرار Replit تعمل كذلك. أوامر الترحيل الأخرى تحتاج المتغيرات في بيئة التنفيذ كما هو موضح في `START-HERE-AR.md`.
8. افحص `/` و`/ar` و`/contact` و`/ar/apply`. الروابط الداخلية تحت العربية تحافظ على `/ar`، وقد يظهر `/ar/` عند العودة للرئيسية، مع canonical موحد إلى `/ar`.

## 2. متغيرات البيئة

ملف `.env.example` يحتوي أسماءً وقيمًا فارغة فقط. القيم التالية تُدخلها أنت في مدير الأسرار؛ الأمثلة هنا ليست مفاتيح فعلية.

| الاسم | الاستخدام |
| --- | --- |
| `NODE_ENV` | `production` على الخادم النهائي، `development` للمعاينة |
| `PORT` | المنفذ الذي توفره الاستضافة؛ يقرأه Express |
| `DATABASE_URL` | رابط PostgreSQL الداخلي من الاستضافة، احتفظ بخيارات TLS التي يحددها المزود |
| `SESSION_SECRET` | سر عشوائي ثابت، 32 حرفًا على الأقل؛ أنشئه بـ `openssl rand -hex 32` |
| `FRONTEND_URL` | الأصل النهائي `https://salsabela.com` دون مسار أو معاملات |
| `DASHBOARD_HOST` | اختياري: `dashboard.salsabela.com` بعد تفعيله على الاستضافة |
| `RESEND_API_KEY` | مفتاح Resend بصلاحيات الإرسال المطلوبة |
| `RESEND_FROM` | عنوان مرسل من نطاق موثق، مثل `Salsabela Academy <notifications@notifications.salsabela.com>` |
| `TURNSTILE_SITE_KEY` | المفتاح العام لويدجت Turnstile؛ أضف النطاق النهائي في إعداداته |
| `TURNSTILE_SECRET_KEY` | المفتاح السري للتحقق من Turnstile في الخادم |
| `INTEGRATION_ENCRYPTION_KEY` | 64 خانة hex لتشفير refresh tokens؛ ولّده بـ `openssl rand -hex 32` واحفظ نسخة احتياطية منفصلة |
| `ZOOM_ACCOUNT_ID` | معرّف الحساب في تطبيق Zoom Server-to-Server OAuth |
| `ZOOM_CLIENT_ID` | معرّف تطبيق Zoom |
| `ZOOM_CLIENT_SECRET` | سر تطبيق Zoom |
| `ZOOM_HOST_USER_ID` | بريد/معرّف صاحب الأكاديمية داخل حساب Zoom نفسه |
| `GOOGLE_CLIENT_ID` | معرّف Google OAuth من نوع Web application |
| `GOOGLE_CLIENT_SECRET` | سر Google OAuth |
| `GOOGLE_CALENDAR_ID` | اختياري؛ فارغ يعني تقويم `primary` المملوك للحساب |
| `TRUST_PROXY_HOPS` | عدد الوكلاء الموثوقين فقط؛ افتراضي 0. اضبطه بعد التحقق من سلسلة الاستضافة |
| `TZ` | `UTC` على خادم التطبيق؛ عرض وقت الطالب يستخدم المنطقة الزمنية من ملفه |

Zoom وGoogle اختياريان؛ اترك مجموعة المزود كاملة فارغة إن لم تجهّزه. الخادم يرفض إعداد مجموعة جزئية في الإنتاج. Resend وTurnstile مطلوبان لإتاحة تدفقات الحسابات في الإنتاج. لا تغيّر مفتاح تشفير التكاملات بعد ربط Google دون إجراء تدوير وإعادة تشفير مدروس.

المتغيرات التشغيلية التالية تُستخدم للأمر المعني فقط وليست أسرار تشغيل دائم: `CONFIRM_PHASE4_MIGRATION=yes`، `CONFIRM_PHASE5_MIGRATION=yes` لترقية إنتاجية راجعت نسختها الاحتياطية، و`ADMIN_PASSWORD_FILE` لإنشاء المالك لأول مرة.

## 3. إنشاء قاعدة بيانات وخدمة Render

1. احفظ المشروع في مستودع Git خاص تملكه، بما فيه `package-lock.json` و`migrations`.
2. في Render اختر **New → PostgreSQL**. اختر المنطقة نفسها التي ستستضيف فيها التطبيق، وخطة مناسبة تدعم الاستمرارية والنسخ الاحتياطية.
3. احفظ **Internal Database URL** في أسرار الخدمة. لا تطبعه في السجلات ولا ترسله في المحادثات.
4. اختر **New → Web Service** واربط مستودعك. اختر بيئة **Node** وخدمة دائمة لا تنام؛ مهام التكامل تعمل كل 15 ثانية داخل العملية.
5. Build command: `npm ci --include=dev && npm run check && npm run lint && npm run build`.
6. Start command: `npm start`. Health check path: `/health/ready`.
7. أدخل المتغيرات في الجدول. ابدأ بنسخة واحدة للخدمة؛ تحديد معدل محاولات المصادقة على مستوى IP في الذاكرة، بجانب قفل الحساب في قاعدة البيانات. التوسع إلى نسخ متعددة يستلزم توحيد هذا الحد أيضًا.
8. عطّل Auto-Deploy أثناء الإعداد. لا تضع الترحيلات أو إنشاء الحساب ضمن Start command.
9. افحص سلسلة الوكلاء الفعلية قبل تعيين `TRUST_PROXY_HOPS`. في إعداد Render المباشر يكون وكيل المنصة هو الطرف المتصل عادةً؛ تحقّق من احتفاظه بعنوان العميل وبروتوكول HTTPS ولا تثق بأي طول سلسلة دون فحص. عند إضافة Cloudflare Proxy أعد الفحص بدل زيادة العدد تخمينيًا.
10. عند جاهزية قاعدة البيانات، طبّق الترحيل المناسب في Shell / Pre-deploy وفق الحالة أدناه، ثم شغّل الخدمة. إعداد pre-deploy يعتمد على خطة Render؛ إذا لم يتوفر، شغّل أمر الترحيل من محطة موثوقة متصلة بالقاعدة قبل إصدار التطبيق.

## 4. الترحيلات والمالك

**قاعدة جديدة فارغة فقط:**

```bash
npm run db:migrate:fresh
npm run seed:programs
```

تنشئ SQL الجداول والفهارس والمحفزات. أمر seed يضيف البرامج الثلاثة المعتمدة فقط، ولا ينشئ مستخدمين أو حصصًا تجريبية.

**قاعدة المرحلة الرابعة الموجودة:**

```bash
CONFIRM_PHASE5_MIGRATION=yes npm run db:migrate:phase5
```

ترحيل `0005_phase5_indexes.sql` يضيف فهارس فقط. يسجل الأمر البصمة ويمنع قبول SQL معدّل بالاسم نفسه. احتفظ بمسار الترحيل اليدوي لقواعد البيانات التي استُخدم فيها سابقًا؛ لا تشغّل `db:migrate:fresh` فوقها إذا لم يكن سجل Drizzle معتمدًا ومتوافقًا.

**إنشاء المالك في قاعدة جديدة:** حضّر ملفًا خاصًا يحوي كلمة مرور قوية من 12–128 حرفًا، واضبط أذوناته `chmod 600`. مرّر مساره عبر `ADMIN_PASSWORD_FILE` ثم نفّذ `npm run admin:bootstrap`. سيطلب الاسم والبريد فقط ولا يطبع كلمة المرور. احذف الملف بعدها. الأمر يرفض إنشاء مالك ثانٍ، ولا يعمل تلقائيًا. للحساب الموجود استخدم إعادة تعيين كلمة المرور.

## 5. ربط النطاقات عبر Cloudflare

1. في خدمة Render افتح **Settings → Custom Domains** وأضف `salsabela.com`، ثم `www.salsabela.com` إذا رغبت في تحويله إلى الأصل، و`dashboard.salsabela.com` إن أردت تفعيله.
2. في Cloudflare اختر منطقة `salsabela.com` ثم **DNS → Records**. سجّل نسخة من السجلات الحالية.
3. أزل أو استبدل سجلات Blogger القديمة الخاصة **بالمضيف الذي تنقله فقط** (`@` أو `www`). لا تحذف سجلات البريد أو التوثيق الأخرى بالجملة.
4. أضف CNAME باسم `@`، والهدف هو اسم `…onrender.com` الحقيقي المعروض لخدمتك، دون `https://` ودون أي مسار. اختر **DNS only** أولًا. Cloudflare يدعم تسطيح CNAME للجذر.
5. أضف `www` و`dashboard` كـ CNAME إلى الهدف الحقيقي نفسه فقط بعد إضافة كل اسم في Render. أزل سجلات A/AAAA المتعارضة لهذه المضيفات إذا كانت تخص الاستضافة القديمة. لا تنشئ عنوان IP تخمينيًا.
6. اطلب التحقق من Custom Domains وانتظر ظهور شهادة HTTPS صالحة في Render. اختبر الموقع بـ HTTPS. يمكنك إبقاء DNS only؛ بعد نجاح الشهادة يمكن تفعيل Proxy إذا احتجت خصائص Cloudflare.
7. عند تفعيل Proxy استخدم **Full (strict)** بعد التأكد من صلاحية شهادة الأصل. لا تستخدم Flexible. لا تضف Cache Everything على HTML أو `/api/*` أو صفحات الحسابات. التخزين الطويل في التطبيق للملفات ذات الأسماء المبصومة داخل `/assets` فقط.
8. اضبط `FRONTEND_URL=https://salsabela.com`. `dashboard.salsabela.com` هو مدخل يعيد التوجيه للموقع الأساسي؛ الجلسة host-only على `salsabela.com` وليست حسابًا أو كوكي مشتركة بين النطاقات.
9. اترك سجلات `notifications.salsabela.com` التي أعطاك إياها Resend كما هي. نطاق الإرسال لا يحتاج خادم ويب أو A/CNAME افتراضيًا. سجلات البريد/التوثيق تكون DNS only عندما يدعم نوعها ذلك.
10. سجّل النطاق النهائي في Turnstile وفي رابط Google OAuth الموضح أدناه. المعاينة على Replit لا تتطلب نقل DNS الآن.

المراجع الرسمية: [Render Node](https://render.com/docs/deploy-node-express-app)، [Cloudflare DNS على Render](https://render.com/docs/configure-cloudflare-dns)، [النطاقات](https://render.com/docs/custom-domains)، [الترحيل قبل النشر](https://render.com/docs/deploys).

## 6. النسخ الاحتياطي والتراجع

- فعّل النسخ المجدولة لدى مزود PostgreSQL حسب خطتك واختبر الاستعادة في **قاعدة منفصلة**.
- قبل التحديث خذ dump باستخدام عميل PostgreSQL متوافق. اضبط بيانات الاتصال في ملف `.pgpass` خاص (`chmod 600`) أو مخزن أسرار؛ لا تكتب كلمة المرور مباشرة في الأمر أو سجل shell.
- مثال بعد ضبط متغيرات PGHOST/PGDATABASE/PGUSER وPGPASSFILE: `pg_dump --format=custom --no-owner --file=salsabela-before-phase5.dump`.
- احفظ dump مشفرًا خارج الخادم، ومعه النسخة الصحيحة من `INTEGRATION_ENCRYPTION_KEY` و`SESSION_SECRET` في مخزن أسرار مستقل.
- افحص الفهرس بـ `pg_restore --list salsabela-before-phase5.dump`. جرّب `pg_restore --no-owner --no-acl --dbname=RESTORE_DATABASE salsabela-before-phase5.dump` على قاعدة فارغة خاصة بالاستعادة. لا تستخدم `--clean` على قاعدة حية دون خطة صريحة.
- للتراجع عن الكود: أوقف النشر التلقائي واختر إصدار Git السابق في Render. فهارس المرحلة الخامسة إضافية ومتوافقة مع المرحلة الرابعة؛ لا يلزم إسقاطها عند التراجع عن الكود.
- إذا لزم استرجاع البيانات: أوقف الكتابة والعامل، خذ نسخة من الوضع الحالي، استعد نسخة احتياطية في قاعدة جديدة، تحقق من أعداد السجلات والوظائف ثم غيّر DATABASE_URL. لا تشغّل نسختين من بيانات مهام التكامل بمفاتيح إنتاجية؛ قد تنفذ عمليات خارجية قديمة.
- عند اختبار dump إنتاجي خارج الإنتاج: **لا تضف مفاتيح Zoom/Google/Resend الإنتاجية**، وعطّل اتصال تلك البيئة بالخدمات الخارجية.

## 7. قائمة ما بعد النشر

- `/health/live` و`/health/ready` يعيدان 200، ولا تُعرض تفاصيل القاعدة.
- الإنجليزية `/` والعربية `/ar` والتنقل والمدونة و404 تعمل. افحص مصدر HTML لا عنصر DOM فقط.
- `/robots.txt` و`/sitemap.xml` يعملان. لا توجد صفحات خاصة في sitemap.
- login/reset/invitation/dashboard عليها `noindex`. اختبر عنوان canonical وhreflang والمشاركة الاجتماعية.
- كوكي الجلسة Secure + HttpOnly + SameSite=Lax ولا تحتوي Domain. تسجيل الخروج وإلغاء الجلسات يعملان.
- جرّب طلب تقييم ورسالة تواصل مخصصين لفحص الإطلاق، ثم المراجعة والدعوة وفتح البريد الحقيقي دون نشر الرموز.
- اختبر Turnstile على النطاق الحقيقي. لا تعتمد تجاوز التطوير.
- اختبر Zoom/Google فقط بعد ربط مفاتيحك: أنشئ درس اختبار مصرحًا، أعد جدولته ثم ألغِه، وتحقق من المزود نفسه وعدم التكرار.
- راقب السجلات الآمنة وFailed syncs، واختر Retry بعد معالجة السبب.
- افحص الهاتف ولوحة المفاتيح وقارئ الشاشة، ثم عطّل/احذف بيانات فحص الإطلاق التي أنشأتها أنت فقط.
