# تحديث لوحة الأكاديمية والمحادثات — 8 أكتوبر 2026

## ما تم تنفيذه

- تحسين بطاقات آراء الطلاب وإضافة أيقونة طالب افتراضية محلية؛ لم تُنشأ آراء أو صور أشخاص وهمية.
- إشعارات Toast عامة في أعلى الشاشة بعد إجراءات API الناجحة، مع رسائل عربية وإنجليزية. الطلبات المضافة للمزامنة تُعرض كطلبات قيد التنفيذ، وليس نجاح اتصال وهميًا.
- إغلاق نافذتي تقرير الحصة وتنبيه الطالب بعد نجاح الخادم فقط. تبقى النافذة مفتوحة عند الفشل لإتاحة التصحيح.
- استبدال نموذج وقائمة الرسائل القديمين بمحادثات مباشرة. زر محادثات عائم داخل الداشبورد، بحث في الطلاب، تمييز غير المقروء، تحميل الرسائل السابقة، وحماية الطلبات من التكرار. الرسائل السابقة محفوظة في الجدول نفسه.
- الطالب يتواصل مع المدير فقط. المدير يتواصل مع الطلاب النشطين فقط. لا حسابات أو واجهات ولي أمر أو معلّم مستقلة.
- مساعد Gemini داخل المحادثات، بلون الأكاديمية، عبر الخادم فقط. لا يقرأ سجلات الطلاب أو محادثاتهم تلقائيًا، ولا يرسل أي إجابة للطلاب نيابة عن المدير.
- تحديث الرسائل كل 3 ثوانٍ، قائمة المحادثات كل 5 ثوانٍ، بيانات اللوحة والإشعارات والحصص كل 10 ثوانٍ. تتوقف دورات الجلب عند إخفاء الصفحة، وتُحدث البيانات عند العودة. هذا تحديث تلقائي بالـpolling وليس WebSocket.
- مركز إشعارات جديد، عرض الكل/غير المقروء، وتحديد الكل كمقروء مع تقييد العملية بحساب المستخدم.
- تحسين توزيع بطاقات النظرة العامة والتصاميم المشتركة، مع تحميل واجهة المحادثات عند الحاجة.
- زر الطالب للحصة المصرّح بها أصبح «ابتدأ الدرس». لا يظهر الرابط إذا لم يمنحه الخادم.
- إنشاء حصص أسبوعية متكررة من عدة أيام وأوقات. معاينة المواعيد، فترة تصل إلى 12 أسبوعًا، بحد أقصى 60 حصة. تُخزن المواعيد UTC ويُحسب كل موعد حسب المنطقة الزمنية، مع رفض الوقت الغائب أو المكرر عند الانتقال الصيفي.
- فحص التعارض مع الحصص والتقييمات قبل إنشاء السلسلة. معاملة واحدة تحفظ كل السلسلة أو تتراجع بالكامل. الطلب المتكرر بالمفتاح نفسه يعيد السلسلة نفسها. كل حصة تدخل نظام Zoom/Calendar الحالي عبر قائمة العمل الحقيقية.
- إعادة تصميم تسجيل الدخول مع إظهار كلمة المرور ومسار واضح للطالب الجديد، والحفاظ على Turnstile والأمان الحاليين. لا أزرار تسجيل اجتماعي غير منفذة.
- مكان الخلفية الاختيارية واضح في `client/src/pages/Auth.tsx`: المتغير `LOGIN_BACKGROUND`. ضع صورة محلية في `client/public/images/` ثم عيّن المسار، مثل `/images/login-background.webp`.
- الترجمات الجديدة كاملة بالعربية والإنجليزية؛ واجهات RTL/LTR والوضع الليلي/النهاري محفوظة.

## التركيب على المشروع الحالي

1. أوقف تشغيل التطبيق أثناء ترحيل قاعدة البيانات وخذ نسخة احتياطية من المشروع وقاعدة PostgreSQL.
2. استبدل الملفات بمحتويات حزمة التعديلات، مع الحفاظ على Secrets وبياناتك. لم تُضمّن أي مفاتيح حقيقية في الحزم.
3. من مجلد المشروع شغّل:

```bash
npm ci
npm run db:migrate:dashboard
npm run verify
npm run dev
```

الأمر `db:migrate:dashboard` يطبّق `migrations/0010_dashboard_communication.sql` فقط. يُعيد التشغيل بأمان ويتحقق من بصمة الترحيل. لا تستخدم ترحيل قاعدة جديدة على قاعدة حالية.

في بيئة `NODE_ENV=production`، بعد النسخ الاحتياطي:

```bash
CONFIRM_DASHBOARD_MIGRATION=yes npm run db:migrate:dashboard
npm run verify
npm start
```

قاعدة جديدة تمامًا: استخدم مسار الترحيل الحالي `npm run db:migrate:fresh`؛ يحتوي سجل الترحيلات الآن على الترحيل الجديد. إنشاء حساب المدير يظل عبر الإجراء الحالي، ولا تُنشأ حسابات تجريبية تلقائيًا.

الجداول/الأعمدة الجديدة: `lesson_series`، `lessons.series_id`، `messages.request_key`، `ai_request_usage`، وفهارس المحادثات ومفاتيح منع التكرار. وظيفة إشعار الرسائل تضيف عنوان الرسالة دون تكرار الإشعار أو كشف نص محادثة في إشعارات الهاتف.

## Gemini

- `GEMINI_API_KEY`: المفتاح الموجود في Secrets؛ لا تضفه إلى كود الواجهة.
- `GEMINI_MODEL`: اختياري. الافتراضي `gemini-3.5-flash-lite`. يمكن تحديد نموذج متاح لحسابك. إعداد التفكير يتوافق مع عائلتي 2.5 Flash و3.
- حدود الخادم: 20 طلبًا لكل حساب خلال ساعة و200 طلب للأكاديمية خلال يوم؛ 2,000 حرف للرسالة، 12 رسالة سياق، 10,000 حرف للسياق، 768 رمز خرج، ومهلة 20 ثانية. الطلبات الفاشلة تُحسب أيضًا لمنع إعادة المحاولة المكلفة بلا حدود.
- حدود يوم الأكاديمية تُحسب خلال نافذة 24 ساعة تبدأ بأول طلب، وليست إعادة ضبط عند منتصف الليل.
- عند غياب المفتاح تظهر حالة «لم يتم إعداد Gemini بعد». عند الرفض أو انتهاء الحصة تظهر رسالة خطأ آمنة. لم تُختبر مفاتيح حسابك ولا استُدعيت Google أو Zoom الحقيقيتان في الاختبارات.
- سجل المساعد مؤقت داخل واجهته، ويُمسح عند إغلاقها. الرسائل البشرية تُحفظ في قاعدة البيانات.
- قد تترتب تكلفة حسب حساب Google وخطة API. الضوابط الحالية تحدّ الاستخدام، ولا تمثل اشتراكًا غير محدود.

## طريقة اختبارك بعد التركيب

1. ادخل بحساب المدير وافتح «المحادثات». اختر طالبًا نشطًا وأرسل رسالة.
2. افتح حساب الطالب في نافذة خاصة أو متصفح آخر. ستظهر الرسالة تلقائيًا خلال ثوانٍ، ويمكنه الرد للمدير فقط.
3. افتح زر المحادثات العائم من النظرة العامة وتأكد من الإرسال وإغلاق النافذة. جرّب زر المساعد بعد إعداد المفتاح.
4. افتح حصة بدأت بالفعل وأرسل تقريرًا مع التقييمات. يجب إغلاق نافذة التقرير وظهور التأكيد. أرسل تنبيهًا واختبر ظهوره في إشعارات الطالب.
5. من «الدروس» افتح إنشاء حصة. في قسم التكرار اختر الطالب والمنطقة الزمنية وتاريخي البداية والنهاية وأضف السبت والثلاثاء بأوقاتهما. راجع المعاينة ثم أنشئ السلسلة.
6. تأكد من ظهور كل الحصص. راقب Jobs في الخدمات المرتبطة لمتابعة Zoom/Calendar. غياب إعداداتها لا يمنع حفظ الحصص، ولا يولّد روابط وهمية.
7. جرّب موعدًا متعارضًا: يجب رفض السلسلة كلها، دون حصص جزئية.
8. افتح إشعارات الطالب، جرّب غير المقروء وتحديد الكل كمقروء.
9. جرّب الهاتف واللغتين والوضعين وتسجيل الدخول وإظهار كلمة المرور.
10. إشعارات الهاتف تحتاج مفاتيح Web Push الحالية، HTTPS، وإذن إشعارات المتصفح/تثبيت التطبيق عندما يتطلب الهاتف ذلك. هذا التحديث لا يتجاوز أذونات الجهاز.

## حدود متبقية

- لا يمكن تأكيد عمل مفاتيح Gemini/Zoom/Google/Resend/Web Push الخاصة بك دون اختبارها في حسابك بعد التحديث.
- السلسلة تحفظ حصصًا منفردة داخل جدول الحصص الحالي. يمكن إعادة جدولة/إلغاء كل حصة بأدواتها الحالية؛ تعديل السلسلة كلها أو إلغاؤها بعملية واحدة ليس ضمن هذا الإصدار.

- يجب تنفيذ اختبار نهائي على الاستضافة الفعلية للتحقق من HTTPS وOrigin وCookies وTurnstile والعامل الخلفي.
- لم تُحذف صفحات الدورات أو أسعارها أو مقالاتك أو الملفات الأساسية. استُبدلت واجهة الرسائل القديمة فقط، مع الحفاظ على بياناتها.
