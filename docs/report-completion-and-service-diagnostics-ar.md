# تحديث التقارير والمحادثات والإشعارات — 9 أكتوبر 2026

## التغييرات

- عند إرسال تقرير حصة بنجاح تُصبح الحصة `completed` في معاملة قاعدة البيانات نفسها. إذا فشل الحفظ تُلغى المعاملة، ولا تُعلّم الحصة مكتملة.
- يختفي زر التقرير بعد الإرسال، وكذلك عند فتح حصة لها تقرير محفوظ مسبقًا. تبقى حماية تقرير واحد لكل حصة وإعادة المحاولة بالمفتاح نفسه دون تقرير إضافي.
- لا يُسجَّل حضور الطالب تلقائيًا لمجرد كتابة التقرير؛ سجل الحضور مستقل.
- واجهة الإشعارات والمحادثات أصبحت بسطوح بيضاء في النهار وكحلية محايدة في الليل، مع لمسات ذهبية وتباين واضح.
- أفاتار الحساب له تصميم مستقل عن صورة آراء الطلاب؛ استُخدمت أيقونات Lucide وBootstrap المرخّصة، لا صور أشخاص مولّدة.
- عاد زر واتساب مرة واحدة للصفحات العامة، باستخدام الرقم الموجود أصلًا في المشروع. لا يظهر داخل مسارات المدير أو الطالب أو الحساب. يُحمَّل المكوّن عند الحاجة دون إدخال مكتبة الحركة في الحزمة الأولية.
- أُصلح خلل عدّاد زر المحادثات: استجابة JSON غير متوقعة كانت قد تؤدي إلى تعطل عرض الداشبورد. يُتحقق الآن من بيانات قائمة المحادثات قبل إدراجها في الواجهة.
- أُضيف تشخيص آمن للمدير عند فشل الخدمات: يفرّق بين غياب مسار API، ورد صفحة HTML، وانتهاء الجلسة، ورفض المصدر، وفشل قاعدة البيانات، ونقص التحديثات، وفشل اتصال المتصفح.
- المساعد ينتظر استجابة الخادم حتى 30 ثانية؛ مهلة طلب Google الداخلية 20 ثانية. مفاتيح Gemini وResend تبقى في الخادم.
- اختبار البريد يميّز رموز Resend المعروفة: مفتاح مرفوض، صلاحيات إرسال، عنوان مرسل، بيانات مرفوضة، وحد استخدام أو طلبات. لا يُعرض نص خطأ الموفّر الخام.
- سجل الخادم يضيف معرّف طلب عشوائيًا ورموز خطأ محددة دون طباعة الاستعلامات أو الأسرار.

## سبب خطأ الخدمات وحدود التحقق

لم تُتح نسخة الخادم الحية أو مفاتيح Replit لهذه المراجعة، لذلك لا يمكن الجزم بسبب فشل خدمات حسابك من الرسالة العامة وحدها. ثبت أن الواجهة القديمة كانت تجمع حالات مختلفة في رسائل عامة، وأن مسار اختبار البريد كان يستخدم قارئ استجابة مختلفًا. أُصلح ذلك وأضيف فحص فعلي للمخطط والإعدادات في الخادم الجاري تشغيله.

فحص «جاهز» يؤكد وجود إعداد أو جدول فقط، ولا يثبت صلاحية المفتاح لدى Google أو Resend. الاختبارات تستخدم مزودات معزولة، ولا ترسل بريدًا حقيقيًا ولا تتصل بحسابات إنتاج.

## تركيب التحديث

1. احتفظ بنسخة احتياطية من الملفات وقاعدة البيانات. ملف التعديلات يطبّق فوق النسخة السابقة `f09eebe`؛ عند وجود اختلافات كبيرة استخدم نسخة المشروع الكاملة واحتفظ بأسرارك خارج الملفات.
2. ارفع ملفات العميل **والخادم** معًا. رفع الواجهة وحدها لا يضيف مسارات API الجديدة.
3. من مجلد المشروع نفّذ:

```bash
npm ci
npm run check
npm run lint
npm run build
npm run dashboard:diagnose
```

4. هذا التحديث لا يضيف ترحيلًا جديدًا. إذا كشف الفحص أن ترحيلات الداشبورد السابقة غير موجودة، وبعد النسخ الاحتياطي وعلى قاعدة البيانات الصحيحة، نفّذ الأوامر اللازمة فقط:

```bash
npm run db:migrate:dashboard
npm run db:migrate:email
npm run db:migrate:single-report
```

هذه الأوامر تتطلب وجود ترحيل متابعة الحصص السابق. في بيئة الإنتاج تتطلب سكربتات الترحيل `CONFIRM_DASHBOARD_MIGRATION=yes`. لا تُشغّل `db:push` بدلًا منها ولا تُنشىء قاعدة فارغة فوق بيانات الأكاديمية.

5. أعد تشغيل Workflow في Replit للمعاينة أو شغّل `npm start` في استضافة Node للإنتاج. استخدم Node 22 أو أحدث.
6. سجّل الدخول من جديد إذا انتهت الجلسة.

## تشخيص المشكلة في نسختك

1. افتح المحادثات ثم جرّب تحميل الطلاب أو المساعد.
2. عند ظهور خطأ اضغط «تشخيص الاتصال» بحساب المدير.
3. إذا ظهر مسار خدمة مفقود: راجع رفع الخادم المطابق وإعادة التشغيل؛ الاستضافة الثابتة وحدها لا تشغّل Express.
4. إذا ظهر رد صفحة بدل JSON: راجع عنوان المعاينة والوكيل أو صفحة الحماية. لا تتجاوز Turnstile ولا تعطّل حماية المصدر.
5. إذا ظهر نقص تحديث قاعدة البيانات: راجع نتيجة `npm run dashboard:diagnose` وطبّق الترحيلات الناقصة فقط.
6. إذا كانت Gemini أو إعدادات البريد ناقصة: ضع المتغيرات في بيئة **الخادم الذي يعمل الآن** ثم أعد تشغيله، دون مسافات زائدة.
7. لإرسال البريد راجع `RESEND_API_KEY` وصلاحياته، و`RESEND_FROM` على النطاق الموثق، و`FRONTEND_URL` بعنوان HTTPS صحيح. في المعاينة يجب أن يكون عنوانًا فعليًا يمكن فتحه، وفي الإنتاج `https://salsabela.com`.
8. إذا كان خطأ المصدر موجودًا خلف وكيل HTTPS، اضبط `TRUST_PROXY_HOPS` وفق عدد الوكلاء الموثوقين في استضافتك. لا تضبطه عشوائيًا ولا تعطّل فحص المصدر.
9. اختبر إرسال البريد من صفحة الخدمات؛ الرسالة الجديدة تحدد فئة رفض Resend. الإرسال إلى بريد المدير في وضع اختبار Resend قد يخضع لقيود حساب الموفّر.
10. إن استمرت المشكلة أرسل صورة رسالة الخطأ ونتيجة التشخيص الآمن أو رمز الطلب من السجل؛ لا ترسل قيمة أي مفتاح.

نموذج Gemini الحالي `gemini-3.5-flash-lite` موثّق رسميًا: https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite . يمكن تغيير `GEMINI_MODEL` إلى نموذج متاح لمشروعك. وجود اسم النموذج لا يثبت صلاحية مفتاح حسابك أو توفر الحصة المسموحة.

## طريقة اختبار سريع بعد الرفع

- افتح حصة بدأت بالفعل ولا يوجد لها تقرير، واكتب التقرير. يجب أن يغلق النموذج ويختفي الزر وتصبح الحصة مكتملة.
- أعد فتح تفاصيل الطالب وحدّث الصفحة: لا يعود زر التقرير لتلك الحصة.
- إرسال تنبيه فقط لا يكمل الحصة تلقائيًا.
- جرّب إشعارات ومحادثات المدير والطالب في الوضعين وعلى الهاتف.
- افتح الصفحة الرئيسية: يظهر واتساب؛ افتح الداشبورد: يختفي واتساب ويظل زر المحادثات.
- جرّب رسالة من المدير إلى طالب نشط ثم رد الطالب، واختبر Gemini برسالة قصيرة.
- اختبر البريد من صفحة الخدمات، ولا تعتبر إدراجه في قائمة الإرسال دليل وصوله؛ راجع النتيجة الفعلية في الموفّر وصندوق البريد.
